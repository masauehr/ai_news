# 生成AI週次ダイジェスト（10/3〜10/10）

## 1. デジタル庁「源内」の国産LLM実証が本格化

デジタル庁が開発した生成AI業務補助システム「源内」の実証が急速に進んでいます。2026年度から国会答弁案の作成を試行しており、職員アンケートでは8割が「業務に寄与している」と回答しました。

さらに注目されるのは、3月に発表した国産LLM 7モデルの大規模実証です。NTT データの「tsuzumi 2」、KDDI/ELYZAの「Llama-3.1-ELYZA-JP-70B」、ソフトバンクの「Sarashina2 mini」、NEC の「cotomi v3」、富士通の「Takane 32B」、Preferred Networks の「PLaMo 2.0 Prime」、カスタマークラウドの「CC Gov-LLM」が選定され、全府省庁の約18万人の職員で2027年3月まで検証されます。7月10日には、さくらインターネットのクラウドを活用した国産クラウド上での実証実験計画も発表されました。

**参照:** [デジタル庁ニュース](https://www.digital.go.jp/news/)

## 2. Microsoft が 1-bit LLM「BitNet b1.58」で CPU 推論の新時代を開く

Microsoft Research が開発した「BitNet b1.58 2B4T」は、全パラメータが {-1, 0, +1} の3値（1.58 bit）という超低ビット量子化LLMの最新成果です。4兆トークンで学習され、わずか 400MB のメモリで動作しながら、同規模の FP16/BF16 モデルと同等の perplexity を実現しました。

最大の特徴は、GPU不要で Apple M2 などの商用CPU上で動作することです。メモリ削減、推論速度の向上、エネルギー効率の改善により、エッジAI・プライバシー重視の環境での活用が期待されます。後付けの量子化ではなく、低ビット前提で学習する新パラダイムを示しており、LLM実運用での省電力化・コスト削減に大きな影響をもたらします。

## 3. Ollama 0.15.5 が OCR 対応・Qwen3-Coder-Next をサポート

ローカルLLM実行環境の Ollama がバージョン 0.15.5 で大幅アップデートされました。Z.ai 開発の「GLM-OCR」（0.9B パラメータ）が新たにサポートされ、手書き文字・数式・表・公印など複雑な文書の読み取り精度が大幅向上しました。

同時に「Qwen3-Coder-Next」もサポートされ、コード生成タスクでの高精度実行が可能になっています。さらに7月30日に追加されたWindows/Mac対応のデスクトップアプリにより、Llama 3.3、DeepSeek-R1、Phi-4、Gemma 3 といった大規模モデルをローカルで簡単に実行できるようになり、ユーザビリティが大幅に向上しました。

**参照:** [Ollama About](https://ollama.com)

## 4. AI エージェント・MCP 統合が業界標準へ

Model Context Protocol（MCP）を活用した AI エージェント統合が急速に進展しています。Anthropic が2024年11月にリリースした MCP は、Claude、Cursor などの主要な AI 環境全体で標準基盤となりました。

Microsoft の「AutoGen MCP拡張機能」（autogen-ext[mcp]）により、AutoGen エージェントが Teams、Slack、Notion、Jira などのシステムとシームレスに連携可能になりました。さらに Microsoft Agent Framework 1.0 では、マルチエージェント・オーケストレーション、マルチプロバイダーモデルサポート、A2A・MCP 経由のクロスランタイム相互運用性を提供し、エンタープライズ環境での活用が加速しています。

## 6. 国産生成AI導入で ChatGPT 首位、企業の実務活用が本格化

ノークリサーチが国内企業800社を対象に実施した調査から、生成AI導入の実態が明らかになりました。対話型では ChatGPT が56.8%で首位、Google Gemini が37%、Claude が6.4% と、海外モデルの採用が主流ながら、企業規模が大きいほど導入・成果実現率が高く、実業務活用が本格化している傾向が確認されました。

文書支援アプリでは Microsoft 365 Copilot が38.8% と突出し、Adobe Acrobat AI アシスタントが15.7% で続くなど、既存エンタープライズツールとの統合進展が加速しています。

**参照:** [ノークリサーチ調査](https://it.impress.co.jp/articles/-/27890)

## 7. ローカルLLM環境構築ガイド・メモリ最適化が実用化段階へ

完全オフラインで動作する LLM 環境構築の実用ガイドが複数公開され、メモリ要件の最適化が進んでいます。Ollama を基盤に VS Code「Continue」、ターミナル「aider」、WebUI「Open WebUI」と連携させ、プライバシー保護・低コスト・無制限開発環境を構築可能になりました。

RAM要件は 8GB→3B～4Bモデル、16GB→9B～14B、24GB→27B が目安とされ、入門には Qwen3.5:9b が推奨されています。RTX3060×2 や RTX5060ti 環境での Qwen3.6 27B、Gemma 4 31B など実用的なスケール検証も進み、個人開発から本番環境まで幅広い選択肢が形成されつつあります。
